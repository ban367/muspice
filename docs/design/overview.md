# 概要: 背景・目的・スコープ

## 背景と課題

Muspiceは、ローカル音楽ファイルをデスクトップで一元管理するためのアプリケーションです。既存の汎用プレーヤーでは、以下の点が開発要件として不足していました。

- フォルダ単位の再帰インポートと重複処理（Skip/Replace）の統合
- DB更新のみ / ファイルタグ更新込みを切り替えられるメタデータ編集
- ローカルSQLiteとFTS5を使った高速検索・フィルタリング
- プレイリスト管理、再生統計（お気に入り・レーティング・再生回数）の統合

## 目的

- ローカル完結（外部通信なし）で動作する音楽管理環境を提供する
- メタデータ編集と検索性を強化し、ライブラリ運用コストを下げる
- Tauri + Rust + SQLiteで、デスクトップ向けに軽量かつ応答性の高い実装を維持する

## 成功指標

| 指標           | 目標                                                           |
| -------------- | -------------------------------------------------------------- |
| 検索開始遅延   | 入力停止から300ms以内に検索処理開始（デバウンス）              |
| 一覧取得       | 曲数の上限なく、ライブラリの全曲を一覧・検索・再生で扱える     |
| インポート処理 | 50件単位トランザクションで大量ファイルでも失敗時の影響を局所化 |
| UI応答性       | 一覧は見えている行だけを描画し、数万曲でも描画負荷を抑制       |

## 対象ユーザー

- プライマリ: ローカルに保持した音楽ファイルを整理・再生したい個人ユーザー
- セカンダリ: タグ編集や再生統計を使って音楽ライブラリを継続運用するユーザー

## スコープ

### In Scope

- 音楽ファイルのインポート（MP3/FLAC/WAV/M4A（AAC・ALAC）/AAC/MP2/AIFF/Ogg Vorbis/Opus）と、インポートしたフォルダ（ライブラリフォルダ）の再スキャン
- メタデータの単体/複数編集（タイトル・アーティスト・アルバムアーティスト・アルバム・作曲者・ジャンル・年・トラック / ディスクの番号と総数・BPM・グループ・コメント・コンピレーション・歌詞）、バリデーション、アルバムアートの埋め込み・取り除き（埋め込みの画像がない曲は、フォルダの`cover.jpg`・`folder.jpg`などを表示）、ファイル情報の表示
- プレイリスト作成・編集・削除・並び替え、M3U（M3U8）の読み込み・書き出し（ほかのアプリで作ったプレイリストの持ち込みと、ほかのアプリ・機器への受け渡し）
- 再生（現在曲管理、アルバムアート取得、ファイル位置表示）。再生は、Rust側の再生エンジン（symphonia + cpal）で行う。ギャップレス再生・クロスフェード・音量の正規化・10バンドのイコライザ・出力デバイスの選択。音量・再生キュー・再生していた曲は、次の起動で復元する（再生位置は復元しない）。macOSでは、キーボードのメディアキー・コントロールセンター・イヤホンのボタンで操作でき、再生中の曲がOSに表示される。メニューバーの「再生」メニューからも操作できる
- 検索/フィルタ、グループ表示（アルバム/アーティスト/ジャンル）
- 再生統計（お気に入り・レーティング・再生回数・スキップ回数・再生履歴）。再生回数は、曲の半分か4分を聴いた時に数える。お気に入りは、行やプレーヤーのハート・右クリックのメニュー（複数の曲をまとめて）で切り替え、サイドバーの「お気に入り」で一覧する
- ほかのプレーヤーからの取り込み（MusicBee・iTunes / ミュージックが書き出すiTunes形式のライブラリXMLから、再生回数・追加日・最終再生日・お気に入り・プレイリスト）
- デバイスへの転送（SDカード・USBメモリなど、マウントされたフォルダへの一方向の同期。全曲か、選んだプレイリスト）

### Out of Scope

- クラウド同期、ユーザーアカウント、外部API連携
- ストリーミング配信サービスの統合
- マルチデバイス同期やサーバーサイド機能（デバイスへの転送はライブラリからの一方向のコピーで、デバイス側の再生回数・レーティングなどは取り込まない）
- デバイスへの転送でのトランスコード（形式の変換）、MTP接続の機器（Android・iPhoneなど）への転送
